# 创新简报实验室：Prompt 组装可理解性审计

## 范围

- 页面：`/brief`
- 用户目标：知道每个选项会改变哪一段 Prompt，并在生图前确认最终实际发送内容。
- 本次只读检查产品代码和现有运行结果，未修改产品实现。

## 流程与健康度

1. 上传并反推内容简报：基本可用，但“创新指导 Prompt”只有文件路径，没有内容或版本。
2. 选择版式/窗型/分栏/画布：能选择，但版式的含义不可见，窗型与分栏×画布的父子关系也不清楚。
3. 编辑衍生方向：内容简报可编辑，但看不到它将插入最终 Prompt 的位置。
4. 点击生成：后端正确组装并保存完整 Prompt，但 UI 生成前无预览、生成后无查看入口。
5. 再生成：使用当前全局左侧选项，不一定沿用该图片“上次”的配置，存在无意改变实验变量的风险。

## 实际组装顺序

```text
core/base.md
+ products/window_sticker/constraints.md
+ layouts/{scene|large_elements|small_scatter}.md
+ 当前方向 textarea 内容
+ window_templates.py 生成的分栏×画布硬约束
```

页面称“六层”，实际可辨识文本块是五层；分栏和画布已在后端合并成同一个模板硬约束块。

## 关键发现

1. `/api/defaults` 已返回每个版式的 `description` 和完整 `text`，前端只取 `id`、`label` 生成下拉框，信息被丢弃。
2. “大尺寸元素”不是一个尺寸参数，而是插入整份 `layouts/large_elements.md`：1–3 个主体、每个约占画布高度 2/3–9/10、仅保留大主体与小点缀两档、禁止中型元素。
3. `large_elements.md` 含雪人、圣诞老人、企鹅、胡桃夹子、雪花等主题特例，会污染泛用主题；其一句话描述还固定写“配雪花点缀”。
4. `compose_generation_prompt()` 会生成最终 Prompt，运行时也会保存 `derived-*-prompt.txt`，但 API 元数据和页面没有暴露这个文件。
5. 页面只显示 `上次：large_elements · 单栏窗...`；“再生成一张”实际读取当前左栏选项，两者可能不一致。
6. 窗型预设会反向设置分栏骨架和画布比例，但界面把三者并列为同级控件，用户难以判断“预设”和“高级拆分参数”的关系。
7. 单张上传阶段并不冻结左侧配置；配置只在点击某方向“生成”时读取。批量自动生成则在提交批次时冻结，但页面没有清楚提示这种差异。

## 优先建议

1. 增加“Prompt 组装预览”抽屉，以五个可折叠色块显示来源、内容和字符数，并提供“最终实际发送 Prompt”页签。
2. 版式下拉下方即时展示人话摘要和关键数字；例如“大尺寸元素：1–3 个主体，高度占 67%–90%，无中型层级”。
3. 将窗型预设作为基础选择；分栏骨架和画布比例收进“高级设置”，并显示预设会修改哪两项。
4. 每个方向保存并展示其当前配置；“再生成”默认沿用上次配置，另设“改用左侧当前配置”。
5. 将版式 Prompt 中的主题特例改成变量化、条件化或通用描述，避免一个版式偷偷引入圣诞素材。
